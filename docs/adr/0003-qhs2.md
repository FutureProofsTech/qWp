# ADR-0003: QHS-2 Smaller Signatures

**Status:** Accepted — QHS-2 implemented; QHS-1 retained  
**Date:** 2026-11-06  
**Deciders:** qWp owner, crypto lead, red team  
**Related:** `docs/05-qhs1.md`, `docs/07-qhs2.md`, `docs/08-qhs2-review.md`, `docs/03-formats.md`

---

## Context

QHS-1 uses 4-bit Winternitz digits: 64 message digits plus 3 checksum digits,
67 chains of 15 steps, and a 2,408-byte signature. The owner asked for a
smaller signature for the next version while keeping QHS-1 available.

The signature size is dominated by the WOTS chains. The auth path is already
minimal for 256 leaves and 32-byte hashes. Truncating hashes below 32 bytes
would reduce the collision security below the 128-bit classical target, so it
was rejected.

## Options

| Base | Chains | Signature | Hashing cost | Result |
|---:|---:|---:|---:|---|
| 4 (QHS-1) | 67 | 2,408 B | 1.0× | current |
| 5 | 55 | 2,024 B | 1.7× | too little gain |
| **6** | **45** | **1,704 B** | **2.8×** | **chosen** |
| 7 | 39 | 1,512 B | 4.9× | slower verify |
| 8 | 34 | 1,352 B | 8.6× | keygen ~100 ms |

## Decision

QHS-2 uses:

- 43 base-64 message digits (256-bit digest with two leading zero bits);
- 2 base-64 checksum digits (checksum range `0..=2709`);
- 45 WOTS chains of 63 steps;
- the same 256-leaf Merkle tree, 64-byte keys, and 256-signature state limit;
- a 1,704-byte signature: `4 + 1,440 + 256 + 4`.

QHS-1 remains unchanged and available through the original `qhs-*` commands.
QHS-2 uses separate `qhs2-*` commands, formats, domain contexts, and cache
fingerprint context.

## Security

The proof structure is unchanged. The reduction loss grows from
`256 × 67 × 15 ≈ 2^18` to `256 × 45 × 63 ≈ 2^19.47`, leaving about 236.5 bits
of WOTS preimage margin. Merkle collision security remains 128 bits, so the
overall classical target remains 128 bits. The quantum target remains at least
64 bits. The stateful leaf invariant is unchanged.

## Measured performance

On the 16-thread reference host, release build:

- keygen: ≈27–28 ms
- cached sign: ≈0.46–0.61 ms
- verify: ≈0.41 ms

QHS-1 remains the faster option; QHS-2 is the smaller-signature option.

## Consequences

- New `qhs2-*` CLI commands and QHS-2 keyed-MAC cache header `[2, 2, 8, 2]`.
- New KAT: `159fb7dd8498d70589da6e4ea1c52d00d86ca070e028ebcbcfa30fd083dd9385`.
- New proof and review documents.
- New tests, attack harness, Kani parser proofs, fuzz coverage, and timing
  harness.
- A fresh 1-hour fuzz soak is required for the QHS-2 release candidate.
- QHS-1 remains tagged `qhs1-rc1`; QHS-2 does not replace it.
