# ADR-0002: QHS-1 — Provable Hash-Based Signature

**Status:** Accepted  
**Date:** 2026-11-06  
**Deciders:** qWp owner, crypto lead, red team  
**Supersedes:** ADR-0001 Option A for the production security path  
**Related:** `docs/05-qhs1.md`, `docs/03-formats.md`, GAP-CRYPTO-0001B

---

## Context

The owner requires the project to be **sound by design and proven by us**, with no demo and no unproven security element.

The topological braid signature cannot meet that requirement at the current parameters:

- B8 / 32 crossings is too small for a meaningful conjugacy-based security claim.
- Published braid signatures are larger and still research-grade.
- The original `P·M·P⁻¹` construction is a proven break.

The braid/Jones engine remains a qWp research module. It is not the production security foundation.

## Decision

Adopt **QHS-1**, a qWp-defined hash-based signature:

- Winternitz one-time signatures with 67 chains of 15 steps.
- Merkle authentication tree of height 8 (256 signatures per key).
- In-tree BLAKE3 with strict domain separation.
- 64-byte public key, 64-byte private key, 2408-byte signature.
- Stateful leaf counter; each leaf is used at most once.

The security proof is written in `docs/05-qhs1.md`: EUF-CMA for at most 256 signing queries, reducing to BLAKE3 preimage/collision resistance plus the stateful-leaf invariant.

## Consequences

- Production signatures are **2.4 KB**, not 160 bytes.
- The private key is stateful and must be persisted after every signature; losing/rolling back the counter can reuse a leaf and break security.
- The topological braid/Jones engine is retained as a research module; it is not used to verify production signatures.
- No standard compliance claim is made.
- The implementation must pass KATs, tamper tests, key-exhaustion tests, Kani bounds proofs, Miri, fuzzing, and the internal red-team suite.

## Rejected alternatives

- Topological braid signature at 160 bytes: unprovable at these parameters.
- External standard signature: violates the zero-standard doctrine.
- Research-only stop: rejected by the owner; QHS-1 gives a provable path.

## Kill criteria

- If the QHS-1 proof is found invalid, stop and fix or revert.
- If the implementation cannot meet the proof obligations, do not ship.
- If the measured attack cost is below the target, do not ship.
