# ADR-0009: QHS-5 512-bit Hash Profile

**Status:** Accepted and implemented — local evidence complete; 1-hour soak pending; `qhs5-rc1` pending

**Date:** 2026-11-09

**Deciders:** qWp owner, crypto lead, red team

**Related:** `docs/16-qhs5.md`, `docs/09-version-family.md`, `docs/03-formats.md`

---

## Context

QHS-1/2/3/3.1/4/4.2 use 32-byte BLAKE3 outputs, targeting 128-bit classical /
≥64-bit quantum security. QHS-5 is the planned 512-bit-hash profile for a
256-bit classical / ~128-bit quantum margin.

The initial plan estimated 45 WOTS chains × 64-byte values (3,400-byte
signature). That estimate is not sound for a 256-bit classical target: 45
base-64 digits bind at most 270 bits, so the 512-bit message digest would be
truncated to 256 bits for the digit encoding. The classical message-collision
bound would be ~128 bits, not 256.

The proof-first correction is to bind the full 512-bit digest:

- 86 message digits × 6 bits = 516 bits, with four leading zero bits;
- 3 base-64 checksum digits (18 bits; checksum range 0..=5,418);
- 89 WOTS chains × 63 steps;
- 64-byte chain values and 64-byte Merkle nodes.

## Decision

QHS-5 uses:

| Parameter | Value |
|---|---:|
| Hash | 512-bit BLAKE3 mode (`H64`) |
| WOTS chains | 89 (86 message + 3 checksum) |
| WOTS chain length | 63 steps |
| Merkle height | 8 |
| Signatures per key | 256 |
| Public key | 72 bytes |
| Private key | 72 bytes |
| Signature | **6,216 bytes** |
| Key header | `[6, 6, 8, 0]` |
| Signature header | `[6, 6, leaf_index LE]` |

The 512-bit mode is:

\[
H64(x) = H32(0x00 \parallel x) \parallel H32(0x01 \parallel x),
\]

with the same construction for derive-key contexts. The two halves are
independent BLAKE3 instances with distinct one-byte domain tags.

Signature layout:

```
4 header | 5,696 WOTS (89 × 64) | 512 auth (8 × 64) | 4 checksum
```

Format version 6 is used because QHS-4.2 already uses format version 5.

## Why this is sound

At 256 signatures per key (no leaf reuse):

- **Message-digit collision:** 86 digits bind 512 bits; collision ≈`2^256`.
- **WOTS one-time:** loss `89 × 63 = 5,607 ≈ 2^12.45`; preimage
  ≈`2^499.5` over the 512-bit hash, capped by the 256-bit collision bound.
- **Merkle collision:** 512-bit output; classical collision ≈`2^256`.
- **Merkle second preimage:** ≈`2^512`.
- **Quantum:** collision ≈`2^128`; preimage ≈`2^256`; conservative margin
  ~128 bits.
- **Statefulness:** each leaf is used once; the CLI cache/state guard detects
  accidental rollback. Restoring both key and guard together remains a local
  hardware-counter limitation.

The overall classical target is 256 bits; the quantum margin is ~128 bits.

## Consequences

- New `qhs5-*` CLI, 72-byte keys, 16,452-byte leaf cache, 38-byte key state
  guard, and 6,216-byte signatures.
- The 512-bit hash mode is `H64(x) = H32(0x00 || x) || H32(0x01 || x)`, with
  derive-key contexts precomputed once per operation. The optimization is
  byte-identical and preserves the proof.
- New `Hash64`/`Hasher64`/`DeriveKey64`/`derive_key64`/`hash64` API in
  `qwp-hash`.
- New platform parallel leaf helper for the 64-byte leaves.
- New tests, attacks, Kani parser proofs, fuzz coverage, timing, coverage,
  mutation, and a fresh 1-hour soak.
- QHS-1/2/3/3.1/4/4.1/4.2 remain unchanged and tagged.
- The plan's 3,400-byte estimate is superseded by the sound 6,216-byte design.
- No 2^64 variant is planned or claimed.
