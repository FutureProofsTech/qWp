# QHS-6 — Classical Hybrid (QHS-5 + Ed25519)

**Status:** Design accepted; implementation and local evidence complete; 1-hour soak pending.

**Security target:** the hybrid is unforgeable if **either** QHS-5 or Ed25519 is
unforgeable. QHS-5 retains its 256-bit classical / ~128-bit quantum margin;
Ed25519 adds classical migration/compliance safety.

**Rule:** No external standard is accepted as proof. This document is the proof.
The Ed25519 implementation follows RFC 8032 and is tested against its vectors,
but the hybrid security argument is written here.

---

## 1. Parameters

| Parameter | Value |
|---|---:|
| Hybrid public key | 108 bytes |
| Hybrid private key | 108 bytes |
| Hybrid signature | 6,284 bytes |
| Key header | `[7, 7, 8, 0]` |
| Signature header | `[7, 7, leaf_index LE]` |
| QHS-5 public/private key | 72 bytes each |
| QHS-5 signature | 6,216 bytes |
| Ed25519 public key | 32 bytes |
| Ed25519 seed | 32 bytes |
| Ed25519 signature | 64 bytes |
| QHS-5 signatures/key | 256 |
| QHS-5 cache | 16,452 bytes |
| QHS-5 state guard | 38 bytes |

Layouts:

```
public key:  4 header | 72 QHS-5 public | 32 Ed25519 public
private key: 4 header | 72 QHS-5 private | 32 Ed25519 seed
signature:   4 header | 6,216 QHS-5 signature | 64 Ed25519 signature
```

## 2. Transcript binding

For a message `m`, QHS-5 public key `P5`, and Ed25519 public key `PE`:

\[
T = H64_{\text{transcript}}(P5 \parallel PE \parallel m).
\]

`H64` is the 512-bit BLAKE3 mode from QHS-5. The transcript is 64 bytes.
Both components sign `T`.

The transcript prevents:

- using a QHS-5 signature for one message with an Ed25519 signature for another;
- mixing keys from different hybrid key pairs;
- cross-version substitution of a QHS-5-only or Ed25519-only signature.

## 3. Keys

Public key (108 bytes):

```
offset  size  field
0       1     version        // 7
1       1     algorithm      // 7
2       1     height         // 8
3       1     reserved       // 0
4       72    QHS-5 public key
76      32    Ed25519 public key
```

Private key (108 bytes):

```
offset  size  field
0       1     version        // 7
1       1     algorithm      // 7
2       1     height         // 8
3       1     reserved       // 0
4       72    QHS-5 private key
76      32    Ed25519 seed
```

The QHS-5 private key contains its own `[6,6,8,0]` header, 64-byte seed,
2-byte counter, and 2 reserved bytes. The QHS-6 private key counter is the
QHS-5 counter at offset `4 + 68 = 72`.

## 4. Signature

```
offset   size    field
0        1       version        // 7
1        1       algorithm      // 7
2        2       leaf_index     // little-endian, 0..=255
4        6216    QHS-5 signature
6220     64      Ed25519 signature
```

Canonical rules:

- Header is exactly `[7, 7, leaf_index LE]`.
- The hybrid leaf index equals the QHS-5 signature leaf index.
- The QHS-5 signature is exactly `[6, 6, leaf_index LE]` + body.
- The Ed25519 signature is exactly 64 bytes.
- No non-canonical trailing data.

## 5. Domain separation

- `qWp QHS-6 transcript`
- `qWp QHS-6 cache fingerprint`
- `qWp QHS-6 cache mac`
- `qWp QHS-6 key state guard`

Ed25519 uses the transcript as its message. The transcript includes both public
keys and the message, so no additional Ed25519 domain context is needed.

## 6. Signing

1. Parse the hybrid private key and check `next_leaf < 256`.
2. Compute the QHS-5 leaves (or load the validated cache).
3. Derive the QHS-5 public key from the leaves.
4. Build the transcript `T`.
5. QHS-5-sign `T` with the next leaf.
6. Ed25519-sign `T` with the Ed25519 seed.
7. Increment the QHS-5 counter and persist the key/state guard before releasing
   the hybrid signature.
8. Assemble the hybrid signature.

The Ed25519 signature is deterministic (RFC 8032); no extra randomness is
needed.

## 7. Verification

1. Parse the hybrid public key and signature.
2. Check the hybrid header, leaf index, and exact lengths.
3. Parse the QHS-5 signature and check its leaf index equals the hybrid one.
4. Rebuild `T` from the public keys and message.
5. Verify the QHS-5 signature on `T`.
6. Verify the Ed25519 signature on `T`.
7. Accept only if both verifications succeed.

## 8. Ed25519 implementation assumptions

- SHA-512 follows FIPS 180-4 and is tested against known vectors.
- Field arithmetic is modulo `2^255 - 19` with five 51-bit limbs.
- Group arithmetic is extended-coordinate edwards25519 with the standard
  `a = -1` addition and doubling formulas.
- Scalar arithmetic is modulo
  `L = 2^252 + 27742317777372353535851937790883648493`.
- Ed25519 follows RFC 8032: SHA-512(seed) expansion, clamping, deterministic
  nonce, `R || S` signature, strict `S < L`, canonical point decoding, and
  small-order point rejection.
- Secret scalar multiplication uses a fixed 256-bit double-and-add loop with
  branchless point selection; field and scalar operations are fixed-width and
  branchless on secret data.
- The implementation is first-party and is not externally audited. The RFC 8032
  vectors and the internal tests are evidence, not a standard-compliance claim.

## 9. Security proof

### Lemma 1 — Transcript collision resistance

`T` binds `P5`, `PE`, and `m`. Two distinct triples collide only with the
collision resistance of `H64`, at most `2^-256` classically and `2^-128`
quantum.

### Lemma 2 — QHS-5 component

Assume QHS-5 is EUF-CMA for up to 256 signatures per key. A hybrid forgery
`(m*, σ5*, σE*)` accepted by the verifier contains a valid QHS-5 signature on
`T* = H64(P5 || PE || m*)`. If the signer never signed `T*`, this is a QHS-5
forgery. If it did sign `T*`, then either `m*` was queried (not a forgery) or
`T*` collided with a transcript for a different message/key triple (Lemma 1).
Thus a hybrid forgery implies a QHS-5 forgery or a transcript collision.

### Lemma 3 — Ed25519 component

Assume Ed25519 is EUF-CMA. The same argument applies to the Ed25519 signature on
`T*`: a hybrid forgery implies an Ed25519 forgery or a transcript collision.

### Theorem — QHS-6 hybrid unforgeability

QHS-6 is EUF-CMA if **either** QHS-5 or Ed25519 is EUF-CMA and `H64` is
collision-resistant for the transcript domain.

**Proof.** A hybrid forgery contains both signatures on the same `T*`. By
Lemma 2, if QHS-5 is secure, the QHS-5 part is a forgery or a transcript
collision. By Lemma 3, if Ed25519 is secure, the Ed25519 part is a forgery or a
transcript collision. Therefore breaking the hybrid requires breaking both
components or finding a transcript collision. ∎

This is the standard AND-composition property: a break of one component does
not break the hybrid. In particular, a quantum break of Ed25519 does not help
forge the QHS-5 part, so the hybrid retains QHS-5's quantum margin.

## 10. Concrete security

- QHS-5: 256-bit classical / ~128-bit quantum.
- Ed25519: ~128-bit classical; broken by a cryptographically relevant quantum
  computer.
- Hybrid classical: at least the stronger of the two, ~256 bits (QHS-5).
- Hybrid quantum: ~128 bits (QHS-5), because the Ed25519 part can be broken but
  the QHS-5 part still must be forged.
- Transcript collision: ~2^256 classical / ~2^128 quantum.
- Signatures per key: 256, inherited from QHS-5; leaf reuse is forbidden.

## 11. Limitations

- Hybrid signature is 6,284 bytes (QHS-5 + 64).
- Ed25519 is a new first-party classical implementation and therefore a new
  audit surface.
- The Ed25519 part is not post-quantum; the hybrid relies on QHS-5 for quantum
  resistance.
- The private key contains both seeds; compromise of the key file compromises
  both components.
- The QHS-5 part is stateful; the counter must be persisted atomically and the
  key must be single-writer.
- The Ed25519 implementation is not externally audited and makes no
  standard-compliance claim.
- No 2^64 variant is planned.

## 12. Attack plan

1. Forge the QHS-5 part after leaf reuse or counter rollback.
2. Forge the Ed25519 part with a wrong key, non-canonical `S`, invalid point,
   or small-order point.
3. Mix a QHS-5 signature and an Ed25519 signature from different messages or
   keys (transcript binding).
4. Tamper with the hybrid header, leaf index, QHS-5 signature, or Ed25519
   signature.
5. Cross-version confusion with QHS-5 or Ed25519-only data.
6. Cache corruption, foreign cache, and state-guard rollback.
7. Timing/fault/DoS.
8. Measure the best-known attack cost.

If any attack succeeds, QHS-6 is broken; fix or stop. No standard fallback.
