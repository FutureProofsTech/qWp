# QHS-3.1 — Tree-Cache Signing Profile

**Status:** QHS-3.1 release candidate tagged `qhs31-rc1`; same signature format as QHS-3.<br>
**Purpose:** Make QHS-3 signing ~4.5× faster without changing keys, signatures, capacity, or the security proof.

---

## 1. What QHS-3.1 is

QHS-3.1 is a **performance profile of QHS-3**, not a new signature version.

- Keys: identical 64-byte QHS-3 keys.
- Signature: identical 1,832-byte QHS-3 signature, version/algorithm `3/3`.
- KAT: identical QHS-3 KAT.
- Capacity: 4,096 signatures per key.
- Security proof: identical `docs/10-qhs3.md`.

QHS-3.1 adds a public **tree cache** and a fast signing API that extracts the
12-node authentication path in O(log N) instead of recomputing range roots.

## 2. Tree cache format

File: `<private-key>.treecache` (262,152 bytes, optional).

```
offset    size    field
0         1       version        // 3
1         1       algorithm      // 3
2         1       height         // 12
3         1       kind           // 1 = tree cache
4         32      fingerprint    // BLAKE3 derive-key("qWp QHS-3.1 cache fingerprint", seed)
36        131072  leaves         // 4096 × 32 bytes, leaf 0 first
131108    131040  nodes          // 4095 × 32 bytes, level 1..12
262148    4       checksum       // BLAKE3(first 262148 bytes)[0..4]
```

Node layout:

- level 1: 2,048 nodes at offset 0;
- level 2: 1,024 nodes at offset 2,048;
- ...
- level 12: 1 node at offset 4,094 (the Merkle root).

The cache is public Merkle data. It contains no WOTS secrets or seed. A missing,
corrupt, foreign, or wrong-kind cache is ignored and rebuilt.

## 3. APIs

- `qhs3_build_tree(leaves, nodes) -> root`
- `qhs3_auth_path_from_tree(leaves, nodes, leaf_index) -> auth_path`
- `Qhs3PrivateKey::sign_with_auth_path(message, auth_path) -> signature`

The existing QHS-3 APIs (`sign`, `sign_with_leaves`) remain available.

## 4. CLI

```bash
qwp qhs31-keygen public.key private.key   # writes private.key.treecache
qwp qhs31-sign private.key message.txt message.sig
qwp qhs31-verify public.key message.txt message.sig
```

QHS-3 commands remain available:

```bash
qwp qhs3-keygen public.key private.key    # writes private.key.cache
qwp qhs3-sign private.key message.txt message.sig
qwp qhs3-verify public.key message.txt message.sig
```

A QHS-3.1 signature verifies with `qhs3-verify`, and a QHS-3 signature verifies
with `qhs31-verify`, because the signature bytes are identical.

## 5. Performance

Measured on the 16-thread reference host, release build:

| Operation | QHS-3 | QHS-3.1 |
|---|---:|---:|
| Keygen | ≈0.40–0.44 s | ≈0.40–0.41 s |
| Cached sign | ≈1.60–1.70 ms | **≈0.35–0.36 ms** |
| Verify | ≈0.39 ms | ≈0.39 ms |
| Signature | 1,832 B | 1,832 B |
| Cache | 131,112 B | 262,152 B |

Signing is about 4.5× faster. Keygen remains dominated by the 4,096-leaf WOTS
computation; verification is unchanged.

## 6. Security

The tree cache is public derived data:

- fingerprint binds it to the seed;
- checksum rejects corruption;
- the verifier recomputes the Merkle root, so altered leaves/nodes cannot
  produce a valid forgery;
- no secret WOTS value is cached.

The QHS-3 proof, assumptions, signature bytes, and KAT are unchanged. QHS-3.1
does not weaken QHS-3.

## 7. Limitations

- Stateful, 4,096 signatures per key.
- 256 KiB tree cache.
- Keygen ≈0.4 s.
- Custom/unaudited like the rest of QHS.
- Not suitable for concurrent or stateless use.
